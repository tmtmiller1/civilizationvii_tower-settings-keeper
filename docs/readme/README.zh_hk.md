# Tower Settings Keeper

一個《文明帝國VII》模組。安裝後，你在其他模組中設定的選項在重新啟動遊戲後仍然保留。它沒有自己的選項，也不會改變遊戲玩法。

## 問題所在

模組把設定儲存在遊戲的 `localStorage` 中。在《文明帝國VII》1.5.0 裡，這個儲存空間有一個缺陷：無論要求的是哪一筆項目，讀取總是傳回儲存空間中的第一筆，而且沒有辦法列出所有項目。只有當某個模組的項目剛好排在最前面時，它才能讀到自己的設定。其他每個模組讀到的都是別的模組的資料，把它當成自己的，並在下次儲存時以自己的名字寫回去。

玩家看到的情況是：選項面板在每次啟動後重設，有時一個模組的設定會出現在另一個模組裡。

大多數選項面板共用一筆名為 `modSettings` 的項目，每個模組佔一個區塊。此外，創意工坊中約有五十個模組帶有一段輔助程式碼，一旦發現第二筆項目就會清空整個儲存空間。只要有一個模組把設定存在自己的項目裡，下次儲存時其他所有模組的設定就會被清掉。

## 這個模組做什麼

它把所有項目都保存在遊戲能夠讀取的唯一一列中，並從該列回應對 `localStorage` 的所有呼叫。

- 使用自己鍵值的模組，其資料會以該鍵值儲存並讀回。
- 共用項目 `modSettings` 和以前一樣運作，每個模組一個區塊，現有的選項面板無需改動。
- 儲存空間始終只回報一筆項目，因此清空儲存空間的輔助程式碼永遠不會執行。
- 如果其他模組已經把儲存空間的順序打亂，本模組會把能辨識的項目移到正確位置，其餘的一律不動，並在每次啟動時重新檢查。

其他模組不需要更新。它可以直接與創意工坊裡已有的模組一起使用。

## 適用於所有模組，無需改動

本模組為所有儲存設定的模組解決這個問題，這些模組保持原樣即可。模組作者不必修改任何東西，也不需要登記。安裝本模組的玩家，其所有模組的設定會一次全部正常運作。

模組作者還有一個額外選項：把同一個檔案放進自己的模組中一起發佈，這樣即使玩家從未安裝本模組，也能受到保護。下文「致模組作者」一節有說明。內建該檔案的模組與本模組可以同時安裝。只有一份副本會執行，也就是最新的那份，其餘的什麼都不做。

## 安裝

在 Steam 創意工坊訂閱，或從最新版本下載 zip，解壓縮到 `~/Library/Application Support/Civilization VII/Mods/`（macOS）或 `%LOCALAPPDATA%\Firaxis Games\Sid Meier's Civilization VII\Mods\`（Windows）。然後在「附加內容」中啟用。沒有任何需要設定的地方。

## 須知

- 從現在起儲存的設定都會保留。安裝本模組之前遺失的設定已經沒有了，除非它們仍以本模組能辨識的項目留在磁碟上。
- 如果儲存空間原本就已損壞，本模組不會猜測無法辨識的項目是哪個模組寫的。如果那筆項目是僅剩的一筆，本模組會圍繞它重建儲存空間並保留其內容。項目的名稱會遺失；之後能辨識該內容的版本會把它放回正確的名稱下。如果有兩筆或更多這樣的項目擋在前面，本模組會在它們之前建立新的根項目，把它們留在磁碟上，並在下次啟動時再試。它絕不會覆寫其他模組的資料。
- 遊戲不保證模組指令碼的執行順序。如果某個模組在自己的指令碼載入的那一刻、在本模組執行之前就讀取設定，那麼在那一次啟動中它看到的仍是舊行為。迄今所有測試啟動中，本模組都是最先執行的。
- 本模組自己的文字已翻譯成遊戲支援的全部十一種語言。
- 儲存空間有 4 MB 的大小上限，是 28 個模組所佔 0.5 MB 的八倍。嘗試超過它的模組只有那一次寫入被拒絕，並保留其之前的設定，同時「選項，附加元件」中會出現一列「已達到儲存上限」，指出該模組的名稱。其他一切不受影響。見下文「負載與上限」。
- 畫面上不會出現任何東西，只有 `Logs/UI.log` 中一行以 `[settings-keeper] ready:` 開頭的記錄。唯一的例外是上面所說的備用情況：此時「選項，附加元件」中會出現一列「重建儲存空間」。按下並確認後，本模組無法辨識的項目會被刪除，儲存空間會寫回為一筆項目。儲存空間恢復正常後，這一列就會消失。

## 負載與上限

所有內容都在一列裡，所以要留意的就是這一列的大小。在測試機上安裝 28 個模組時，這一列約為 0.5 MB，幾乎全部是某一個模組的遊戲歷史。一個選項面板只增加幾百位元組。一次寫入會序列化整列，在這個大小下約 8 ms，每個工作只做一次，不論其中寫入多少個值。模組的數量本身無關緊要，關鍵是它們存了多少。

為了找出引擎在哪裡撐不住，一個探針在裝有同樣 28 個模組的「立即開始」遊戲中，透過本模組讓這一列每步增長 1 MB，並用單獨的啟動分別測試各個環節。

| 列大小 | 一次寫入（序列化並儲存） | 寫入後讀取一個鍵 |
|---|---|---|
| 0.5 MB，真實儲存 | 8 ms | 2 ms |
| 5 MB | 71 ms | 20 ms |
| 10 MB | 101 ms | 64 ms |
| 13 MB | 141 ms | 67 ms |
| 一次寫入 16 MB | 102 ms | |
| 20 MB，每次增加 1 MB | 197 ms | |

在任何大小下都沒有遺失或損壞，儲存空間始終是一列。有上限的是遊戲處理程序本身。當這一列被連續多次讀取並重寫時，它在 14 MB 那一步停止了，沒有當機報告；只重寫時則在 21 MB 那一步停止。一個 14 MB 的儲存空間能在主選單和遊戲中載入，所有鍵都可讀，但在這一列再被讀取並重寫一次後停止了。停止時處理程序佔用 1.9 GB，所以上限是遊戲的記憶體，不是儲存空間。

因此本模組拒絕任何會使這一列超過 4 MB 的寫入，這是遊戲停止的最低大小的四分之一。被拒絕的寫入會擲出與瀏覽器 localStorage 已滿時相同的 `QuotaExceededError`，面向 Web API 編寫的模組已經知道它的含義。該模組之前的值保留，其他模組不受影響，記錄檔記下模組名稱和大小，「選項，附加元件」顯示一列「已達到儲存上限」，內容相同，並有一個「確定」可以清除它。上限是 `ui/settings-keeper.js` 開頭的一個常數。

## 移除本模組

通常無需做任何事。儲存空間只有一列，所以遊戲會像以前一樣先讀取 `modSettings`，其他模組能找到自己的區塊。多出來的只是幾個它們會忽略的內部欄位。如果「選項」中顯示「重建儲存空間」這一列，請在停用本模組之前先按下它。否則其他模組的輔助程式碼會在下次儲存時清空儲存空間。

## 致模組作者

你不需要做任何事。無論你的模組使用共用項目 `modSettings` 還是自己的鍵值，在安裝了本模組的環境中，你的模組的設定都能正常運作。

如果你希望玩家不必安裝本模組也能受到保護，可以把這個修正放進你自己的模組中。只需一個檔案和 modinfo 中的兩行，你的設定程式碼保持不變。說明見 [embed/README.md](../../embed/README.md)（英文），也可以從最新版本取得 `settings-keeper-embed-<version>.zip`。
